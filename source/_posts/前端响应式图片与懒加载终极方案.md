## 前言

图片是前端页面中**最重的资源**。一个典型的新闻页面，图片占页面总大小的 **60%-80%**。

优化图片加载，是前端性能优化中 ROI 最高的举措之一。

本文将覆盖图片优化的**完整链路**：从选择正确的格式 → 响应式尺寸 → 懒加载 → 占位策略 → 缓存。

---

## 一、选择正确的图片格式

### 1.1 格式对比

| 格式 | 压缩率 | 透明通道 | 动画 | 浏览器支持 | 适用场景 |
|------|--------|---------|------|-----------|---------|
| JPEG | 中 | ❌ | ❌ | 全支持 | 照片、复杂颜色图 |
| PNG | 低（无损） | ✅ | ❌ | 全支持 | 图标、截图、需要透明的图 |
| GIF | 高 | ✅ | ✅ | 全支持 | 简单动画 |
| **WebP** | **高** | ✅ | ✅ | 95%+ | **通用替代 JPEG/PNG** |
| **AVIF** | **最高** | ✅ | ✅ | 80%+ | **极致压缩** |
| SVG | 无损矢量 | ✅ | ✅ | 全支持 | 图标、Logo、插画 |

### 1.2 推荐方案

```html
<!-- 使用 <picture> 按浏览器支持选择最佳格式 -->
<picture>
  <source type="image/avif" srcset="photo.avif">
  <source type="image/webp" srcset="photo.webp">
  <img src="photo.jpg" alt="描述">
</picture>
```

**效果：** 支持 AVIF 的浏览器加载 AVIF（体积最小），支持 WebP 的加载 WebP，都不支持的降级到 JPEG。

## 二、响应式图片——给不同屏幕不同尺寸

### 2.1 srcset + sizes

```html
<!-- srcset：告诉浏览器可选的图片资源及宽度 -->
<!-- sizes：告诉浏览器图片在不同视口下的显示宽度 -->
<img
  src="photo-800.jpg"
  srcset="
    photo-400.jpg 400w,
    photo-800.jpg 800w,
    photo-1200.jpg 1200w,
    photo-1600.jpg 1600w
  "
  sizes="
    (max-width: 600px) 100vw,
    (max-width: 1200px) 50vw,
    33vw
  "
  alt="响应式图片"
>
```

**浏览器自动选择**最适合当前设备和网络状况的图片——不需要 JavaScript！

| 断点 | 视口宽度 | sizes 值 | 实际渲染宽度 | 选用的图片 |
|------|---------|----------|-------------|-----------|
| 手机 | 375px | 100vw | 375px | photo-400.jpg |
| 平板 | 768px | 50vw | 384px | photo-400.jpg |
| 桌面 | 1440px | 33vw | 475px | photo-800.jpg |
| 高分屏 Mac | 1440px (2x) | 33vw | 实际需要 950px | photo-1200.jpg |

### 2.2 艺术指导（Art Direction）

```html
<!-- 不同视口展示图片的不同裁切版本 -->
<picture>
  <source media="(min-width: 1024px)" srcset="hero-desktop.jpg">
  <source media="(min-width: 640px)" srcset="hero-tablet.jpg">
  <img src="hero-mobile.jpg" alt="横幅">
</picture>
```

## 三、懒加载

### 3.1 Native Lazyload（浏览器原生）

```html
<!-- loading="lazy" 让浏览器原生支持懒加载 -->
<img src="photo.jpg" loading="lazy" alt="延迟加载图片">

<!-- 对首屏重要的图片用 eager -->
<img src="hero.jpg" loading="eager" alt="首屏大图">

<!-- 使用 fetchpriority 提示优先级 -->
<img src="hero.jpg" loading="eager" fetchpriority="high" alt="首屏关键图片">
```

**支持情况：** 所有现代浏览器已支持 `loading="lazy"`。

### 3.2 Intersection Observer 实现

```ts
function lazyLoadImages() {
  const observer = new IntersectionObserver(
    (entries) => {
      entries.forEach(entry => {
        if (entry.isIntersecting) {
          const img = entry.target as HTMLImageElement
          img.src = img.dataset.src!      // 替换真实地址
          img.srcset = img.dataset.srcset! // 替换 srcset
          img.onload = () => img.classList.add('loaded')
          observer.unobserve(img)
        }
      })
    },
    { rootMargin: '200px' } // 提前 200px 开始加载
  )

  document.querySelectorAll('img[data-src]').forEach(img => observer.observe(img))
}
```

```html
<!-- 使用 data-src 占位 -->
<img data-src="photo.jpg" data-srcset="photo-400.jpg 400w, photo-800.jpg 800w" class="lazy" alt="懒加载图片">
```

## 四、占位策略

### 4.1 模糊占位图（Blur-up）

```css
.blur-up {
  filter: blur(20px);    /* 先展示模糊小图 */
  transition: filter 0.3s;
}

.blur-up.loaded {
  filter: blur(0);       /* 原图加载完后渐变为清晰 */
}
```

### 4.2 LQIP（Low Quality Image Placeholders）

生成一个极小（20-50px）的模糊图，Base64 内联到 HTML 中：

```html
<img
  src="photo.jpg"
  style="background: url(data:image/webp;base64,...); background-size: cover;"
  alt="带占位图"
>
```

### 4.3 骨架屏

```css
.skeleton {
  background: linear-gradient(90deg, #eee 25%, #f5f5f5 37%, #eee 63%);
  background-size: 200% 100%;
  animation: shimmer 1.4s infinite;
}

@keyframes shimmer {
  0% { background-position: 200% 0; }
  100% { background-position: -200% 0; }
}
```

## 五、CDN 与缓存策略

### 5.1 图片 CDN 处理

```ts
// 阿里云 OSS 图片处理（在 URL 后加参数）
const url = 'https://bucket.oss-cn-hangzhou.aliyuncs.com/photo.jpg'

// 缩放到 400px
const resized = url + '?x-oss-process=image/resize,w_400'

// 转为 WebP
const webp = url + '?x-oss-process=image/format,webp'

// 图片 CDN 服务商（自动优化）
// imgix: /photo.jpg?w=400&fm=webp
// Cloudinary: /c_scale,w_400/f_webp/photo.jpg
// Vercel Image Optimization: 内置 <Image> 组件
```

### 5.2 Cache-Control

```nginx
# Nginx 配置——图片强缓存
location ~* \.(jpg|jpeg|png|gif|webp|avif)$ {
  expires 365d;
  add_header Cache-Control "public, immutable";
}
```

## 六、完整方案总结

```
原始图片
    ↓
选择最佳格式（AVIF > WebP > JPEG）         ← 格式优化
    ↓
生成多组尺寸（400w/800w/1200w/1600w）       ← 响应式
    ↓
使用 srcset + sizes 或 <picture>            ← 浏览器选最优
    ↓
首屏 → loading="eager"                     ← 立即加载
非首屏 → loading="lazy" 或 IntersectionObserver ← 懒加载
    ↓
占位策略（LQIP / 骨架屏 / Blur-up）         ← 体验优化
    ↓
CDN 分发 + 强缓存                           ← 传输优化
```

## 七、性能提升效果

实施上述优化后，一个典型内容网站的图片性能提升：

| 图片传输大小 | 2.4MB | 420KB | **-82%** |
