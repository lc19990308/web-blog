## 前言

性能优化不是炫技，而是用户体验的底线。研究表明：
- 页面加载时间从 1s 增加到 3s，**跳出率增加 32%**
- 加载时间从 1s 增加到 5s，**跳出率增加 90%**
- 电商网站加载慢 100ms，**转化率降低 7%**

本文从**网络加载** → **资源优化** → **渲染性能** 三个维度，给出可直接落地的优化方案。

## 一、网络加载优化

### 1.1 减少 HTTP 请求

**合并文件**：将小文件合并，减少请求数。

```javascript
// Webpack / Vite 配置
// 将小于 10KB 的图片转为 base64 内联
{
  test: /\.(png|jpg|gif)$/,
  type: 'asset',
  parser: {
    dataUrlCondition: { maxSize: 10 * 1024 }
  }
}
```

### 1.2 使用 CDN

```html
<!-- 将静态资源托管到 CDN -->
<script src="https://cdn.jsdelivr.net/npm/vue@3/dist/vue.global.min.js"></script>

<!-- Webpack 配置 externals，避免打包三方库 -->
<!-- webpack.config.js -->
module.exports = {
  externals: {
    vue: 'Vue',
    'vue-router': 'VueRouter',
  },
}
```

### 1.3 启用 Gzip / Brotli 压缩

```nginx
# Nginx 配置 Gzip
gzip on;
gzip_types text/plain text/css application/json application/javascript text/xml;
gzip_min_length 1024;
gzip_comp_level 6;

# Brotli（比 Gzip 压缩率高 20-30%）
brotli on;
brotli_types text/plain text/css application/javascript;
```

**效果：** JS/CSS 文件压缩后体积减少 **70-80%**。

### 1.4 使用 HTTP/2

HTTP/2 支持**多路复用**，一个连接并行传输多个文件，解决 HTTP/1.1 的队头阻塞问题：

```nginx
listen 443 ssl http2;
```

### 1.5 预加载关键资源

```html
<!-- preload：当前页面需要的关键资源 -->
<link rel="preload" href="font.woff2" as="font" crossorigin>

<!-- prefetch：下一页可能需要的资源 -->
<link rel="prefetch" href="next-page.js">

<!-- preconnect：提前建立连接 -->
<link rel="preconnect" href="https://api.example.com">
```

## 二、资源优化

### 2.1 图片优化

图片通常是页面**最大的资源**，优化收益最高：

```javascript
// Vite 配置图片压缩
import viteImagemin from 'vite-plugin-imagemin'

export default {
  plugins: [
    viteImagemin({
      gifsicle: { optimizationLevel: 7 },
      optipng: { optimizationLevel: 7 },
      mozjpeg: { quality: 80 },
      pngquant: { quality: [0.8, 0.9] },
      webp: { quality: 75 },
    }),
  ],
}
```

**图片选型：**

| 格式 | 适用场景 | 压缩率 |
|------|---------|--------|
| WebP | 照片、复杂图像 | 比 JPEG 小 **25-35%** |
| AVIF | 下一代格式 | 比 WebP 小 **20-30%** |
| SVG | 图标、Logo | 无损、可缩放 |
| 懒加载图片 | 首屏以下图片 | 减少首屏加载量 |

```html
<!-- 懒加载：loading="lazy" 原生支持 -->
<img src="photo.jpg" loading="lazy" alt="描述" />

<!-- 响应式图片 -->
<img
  srcset="photo-400w.jpg 400w, photo-800w.jpg 800w"
  sizes="(max-width: 600px) 400px, 800px"
  src="photo-800w.jpg"
/>
```

### 2.2 JavaScript 优化

```javascript
// 代码分割：Vite / Webpack 自动按路由分割
const routes = [
  { path: '/about', component: () => import('./views/About.vue') },
]

// 动态导入：按需加载非核心库
button.addEventListener('click', async () => {
  const moment = await import('moment')
  console.log(moment().format())
})
```

| 优化策略 | 效果 |
|---------|------|
| Tree Shaking | 移除未使用的代码，减少 20-60% |
| 代码分割 | 首屏只加载必要 JS |
| 动态导入 | 非核心功能延迟加载 |
| 移除 console | 生产环境移除 console.log |

```javascript
// Vite 生产环境自动移除 console
// vite.config.js
export default {
  esbuild: {
    drop: process.env.NODE_ENV === 'production' ? ['console', 'debugger'] : [],
  },
}
```

### 2.3 CSS 优化

```css
/* 移除未使用的 CSS（PurgeCSS 自动完成） */
/* 使用后：从 200KB → 15KB */

/* 关键 CSS 内联：首屏样式直接写在 HTML 中 */
<style>
  .header { /* 首屏关键样式 */ }
  .hero { /* 首屏关键样式 */ }
</style>
<link rel="stylesheet" href="styles.css" media="print" onload="this.media='all'">
```

### 2.4 字体优化

```css
/* 使用 font-display 控制字体加载行为 */
@font-face {
  font-family: 'CustomFont';
  src: url('font.woff2') format('woff2');
  font-display: swap; /* 先用系统字体，加载后替换 */
}

/* 只加载需要的字符集 */
/* 比如只加载中文常用字，可减少 90%+ 字体体积 */
```

## 三、渲染性能优化

### 3.1 减少重排（Reflow）与重绘（Repaint）

```javascript
// ❌ 每次读取 + 写入都会触发重排
const height = element.offsetHeight  // 读取
element.style.height = height + 10 + 'px'  // 写入
element.style.width = '100px'              // 写入（再次重排）

// ✅ 使用 requestAnimationFrame 批量写入
requestAnimationFrame(() => {
  element.style.height = height + 10 + 'px'
  element.style.width = '100px'
})
```

**触发重排的操作：**
- 读取 `offsetHeight`、`offsetWidth`、`scrollTop`、`getComputedStyle`
- 修改 `width`、`height`、`margin`、`padding`、`border`
- `display: none` 到 `display: block`

### 3.2 使用虚拟滚动

当列表有**数千条**数据时，不要一次性渲染所有 DOM：

```vue
<!-- 大数据列表时，只渲染可视区域 -->
<template>
  <div ref="container" @scroll="onScroll" style="height: 400px; overflow: auto">
    <div :style="{ height: totalHeight + 'px' }">
      <div
        v-for="item in visibleItems"
        :key="item.id"
        :style="{ position: 'absolute', top: item.top + 'px' }"
      >
        {{ item.name }}
      </div>
    </div>
  </div>
</template>
```

或使用成熟的虚拟滚动库（`vue-virtual-scroller`、`react-window`）。

### 3.3 动画性能

```css
/* ✅ GPU 加速：只使用 transform 和 opacity */
.element {
  transform: translateX(100px);
  opacity: 0.5;
  will-change: transform; /* 提示浏览器优化 */
}

/* ❌ 避免：触发重排的属性 */
.element {
  left: 100px;  /* 触发重排 */
  top: 50px;    /* 触发重排 */
}
```

### 3.4 事件节流与防抖

```javascript
// 防抖：搜索输入（用户停止输入后才触发）
function debounce(fn, delay = 300) {
  let timer
  return (...args) => {
    clearTimeout(timer)
    timer = setTimeout(() => fn(...args), delay)
  }
}

// 节流：滚动事件（固定频率触发）
function throttle(fn, interval = 100) {
  let last = 0
  return (...args) => {
    const now = Date.now()
    if (now - last >= interval) {
      last = now
      fn(...args)
    }
  }
}

window.addEventListener('scroll', throttle(handleScroll, 100))
```

### 3.5 长任务拆分

```javascript
// ❌ 同步任务阻塞主线程 500ms，导致页面卡顿
function processLargeData(items) {
  items.forEach(item => heavyComputation(item))
}

// ✅ 拆分为微任务，让浏览器有喘息机会
async function processLargeData(items) {
  const chunkSize = 50
  for (let i = 0; i < items.length; i += chunkSize) {
    const chunk = items.slice(i, i + chunkSize)
    chunk.forEach(item => heavyComputation(item))
    await new Promise(resolve => setTimeout(resolve, 0)) // 让出主线程
  }
}
```

## 四、性能监控

### 4.1 Core Web Vitals

Google 定义的三个核心指标：

| 指标 | 含义 | 目标 |
|------|------|------|
| **LCP** | 最大内容绘制 | ≤ 2.5s |
| **FID** | 首次输入延迟 | ≤ 100ms |
| **CLS** | 累计布局偏移 | ≤ 0.1 |

### 4.2 测量工具

```javascript
// 使用 Performance API
window.addEventListener('load', () => {
  // 获取 LCP
  new PerformanceObserver((list) => {
    const entries = list.getEntries()
    console.log('LCP:', entries[entries.length - 1].startTime)
  }).observe({ type: 'largest-contentful-paint', buffered: true })

  // 获取 FID
  new PerformanceObserver((list) => {
    list.getEntries().forEach(entry => console.log('FID:', entry.processingStart - entry.startTime))
  }).observe({ type: 'first-input', buffered: true })
})
```

**推荐工具：**
- **Lighthouse**：Chrome 内置审计工具
- **WebPageTest**：在线测速工具
- **Chrome DevTools Performance**：性能分析面板

## 总结

性能优化不是一次性的工作，而是需要**持续监控和迭代**的过程。核心思路：

1. **测量 → 优化 → 再测量**（先找到瓶颈）
2. **优先优化网络层**（收益最大）
3. **资源加载做懒加载**（减少首屏压力）
4. **渲染避免重排**（保持 60fps）
5. **监控 Core Web Vitals**（用数据说话）
