## 前言

低代码（Low-Code）和可视化搭建在前端领域已经成为一个重要的细分方向。从页面搭建、表单配置到业务流程编排，"拖拽生成"的能力正在改变前端的交付方式。

本文将从**技术原理**角度，拆解一个可视化搭建平台的完整架构。

---

## 一、低代码平台的架构分层

```
┌─────────────────────────────────┐
│         业务组件库               │  ← 预制组件
├─────────────────────────────────┤
│         渲染引擎                 │  ← 运行时解析 Schema 并渲染
├─────────────────────────────────┤
│         设计器（编辑器）          │  ← 拖拽、配置、预览
├─────────────────────────────────┤
│         出码引擎                 │  ← 导出代码/JSON Schema
├─────────────────────────────────┤
│         托管/发布服务             │  ← 部署与存储
└─────────────────────────────────┘
```

**核心思想：** 一切皆可描述——用**一份 Schema（JSON 描述）** 来表示 UI 和交互逻辑。

---

## 二、组件模型设计

每个可拖拽的组件需要统一的接口：

```ts
interface ComponentMeta {
  name: string           // 组件名
  title: string          // 展示名
  props: PropMeta[]      // 可配置的属性
  snippets: Snippet[]    // 预设模板
}

interface PropMeta {
  name: string
  type: 'string' | 'number' | 'boolean' | 'select' | 'json'
  defaultValue?: any
  options?: { label: string; value: any }[]  // select 类型的选项
}
```

**设计原则：** 组件无感知——组件不需要知道自己被用于低代码平台，只需遵循 props 约定。

## 三、Schema 驱动渲染

### 3.1 Schema 定义

```json
{
  "componentName": "Page",
  "props": { "style": { "padding": "24px" } },
  "children": [
    {
      "componentName": "Card",
      "props": { "title": "用户信息" },
      "children": [
        {
          "componentName": "Form",
          "props": {},
          "children": [
            {
              "componentName": "Input",
              "props": { "name": "username", "label": "用户名" }
            },
            {
              "componentName": "Select",
              "props": {
                "name": "gender",
                "label": "性别",
                "options": [
                  { "label": "男", "value": "male" },
                  { "label": "女", "value": "female" }
                ]
              }
            }
          ]
        }
      ]
    }
  ]
}
```

### 3.2 渲染引擎核心

```tsx
function Renderer({ schema }: { schema: SchemaNode }) {
  const Component = registry.get(schema.componentName)
  if (!Component) return <div>未知组件: {schema.componentName}</div>

  const children = schema.children?.map((child, i) => (
    <Renderer key={i} schema={child} />
  ))

  return (
    <Component {...schema.props}>
      {children}
    </Component>
  )
}
```

## 四、拖拽引擎实现

### 4.1 DnD 核心逻辑

```ts
// 使用 dnd-kit 实现
import { DndContext, useDraggable, useDroppable } from '@dnd-kit/core'

function DraggableComponent({ meta }: { meta: ComponentMeta }) {
  const { attributes, listeners, setNodeRef, transform } = useDraggable({
    id: meta.name,
    data: meta
  })

  return (
    <div ref={setNodeRef} {...listeners} {...attributes}>
      {meta.title}
    </div>
  )
}

function Canvas() {
  const { setNodeRef, isOver } = useDroppable({ id: 'canvas' })

  return (
    <div
      ref={setNodeRef}
      style={{ outline: isOver ? '2px dashed #1890ff' : 'none' }}
    >
      <Renderer schema={currentSchema} />
    </div>
  )
}
```

### 4.2 属性面板

当选中组件时，根据其 `ComponentMeta.props` 动态渲染属性编辑器：

```tsx
function PropEditor({ meta, value, onChange }: {
  meta: PropMeta
  value: any
  onChange: (v: any) => void
}) {
  switch (meta.type) {
    case 'string':
      return <Input value={value} onChange={onChange} />
    case 'number':
      return <InputNumber value={value} onChange={onChange} />
    case 'boolean':
      return <Switch checked={value} onChange={onChange} />
    case 'select':
      return <Select options={meta.options} value={value} onChange={onChange} />
    case 'json':
      return <CodeEditor value={JSON.stringify(value, null, 2)} onChange={v => onChange(JSON.parse(v))} />
    default:
      return <div>未知属性类型</div>
  }
}
```

## 五、出码引擎

将 Schema 转换为可运行的源代码：

```ts
function generateCode(schema: SchemaNode, indent = 0): string {
  const prefix = '  '.repeat(indent)
  const propsStr = Object.entries(schema.props)
    .map(([k, v]) => `${k}={${JSON.stringify(v)}}`)
    .join('\n' + prefix + '  ')

  if (!schema.children?.length) {
    return `${prefix}<${schema.componentName} ${propsStr} />`
  }

  const childrenCode = schema.children
    .map(child => generateCode(child, indent + 1))
    .join('\n')

  return `${prefix}<${schema.componentName} ${propsStr}>\n${childrenCode}\n${prefix}</${schema.componentName}>`
}
```

## 七、总结与思考

低代码不是"代替程序员"，而是**让程序员专注于更有价值的组件和逻辑开发**，把重复的页面搭建工作交给工具。

作为前端开发者，理解低代码的底层原理，能让你：
1. 更好地设计和实现组件库
2. 在需要时搭建自己的内部工具
3. 更深刻地理解"声明式 UI"的本质
