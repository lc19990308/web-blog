## 前言

打开一个网页，浏览器背后做了大量工作。理解**关键渲染路径**（Critical Rendering Path）是前端性能优化的基础。

整个过程分为 6 步：

```
URL → DNS 解析 → TCP 连接 → HTTP 请求 → 解析 HTML → 渲染页面
                                                    │
                          ┌─── HTML → DOM ──┐        │
                          │   CSS → CSSOM    ├──→ 布局 → 绘制
                          │   JS → 解析阻塞  │
                          └─────────────────┘
```

---

## 一、导航阶段

### 1.1 DNS 解析

```
浏览器输入 baidu.com → DNS 服务器 → 返回 IP 地址 220.181.38.148
```

DNS 解析通常耗时 **20-120ms**。优化方式：

```html
<!-- DNS 预解析 -->
<link rel="dns-prefetch" href="//api.example.com">
```

### 1.2 TCP 三次握手

```
客户端 → SYN          → 服务端
客户端 ← SYN + ACK    ← 服务端
客户端 → ACK          → 服务端
```

每次握手约 1 个 RTT（往返时间）。**HTTP/2 多路复用**减少连接数。

## 二、解析阶段

### 2.1 构建 DOM 树

```html
<html>
<head>...</head>
<body>
  <div>
    <p>Hello</p>
  </div>
</body>
</html>
```

浏览器将 HTML 解析为 DOM 树：

```
document
  └── html
       ├── head
       └── body
            └── div
                 └── p
                      └── "Hello"
```

### 2.2 构建 CSSOM 树

```css
body { font-size: 16px; }
div { color: red; }
p { font-weight: bold; }
```

CSS 解析**不会阻塞 DOM 构建**，但会**阻塞渲染**——因为浏览器不知道样式前不会渲染。

```html
<!-- 关键 CSS 内联，非关键 CSS 延迟加载 -->
<link rel="stylesheet" href="critical.css" />
<link rel="stylesheet" href="non-critical.css" media="print" onload="this.media='all'">
```

### 2.3 JavaScript 阻塞

```html
<!-- ❌ 阻塞解析：遇到 script 会停下 DOM 解析 -->
<script src="app.js"></script>

<!-- ✅ async：下载完立即执行（不保证顺序）-->
<script async src="app.js"></script>

<!-- ✅ defer：DOM 解析完再执行（保证顺序）-->
<script defer src="app.js"></script>
```

| 属性 | 下载 | 执行时机 |
|------|------|---------|
| 无 | 遇到时 | 立即执行，阻塞解析 |
| `async` | 异步下载 | 下载完立即执行 |
| `defer` | 异步下载 | DOM 解析完后执行 |

**推荐：** `<script defer>` 放在 `<head>` 中。

## 三、渲染阶段

### 3.1 构建渲染树

DOM + CSSOM → **渲染树（Render Tree）**：

```
DOM 树                         CSSOM
document                    body { font-size: 16px }
  └── html                  div { color: red }
       ├── head             p { font-weight: bold }
       └── body
            └── div
                 └── p
```

只包含**可见元素**（`display: none` 不在渲染树中，`visibility: hidden` 在）。

### 3.2 布局（Layout）

计算每个可见元素在视口中的**几何位置**（宽、高、x、y）：

```
浏览器计算：div 宽度 300px，高度 100px，left 50px，top 20px
```

**触发重排（Reflow）的操作：**
- 修改 `width` / `height` / `margin` / `padding`
- 修改 `display: none → block`
- 读取 `offsetHeight` / `offsetWidth` / `scrollTop`

### 3.3 绘制（Paint）

将元素的**像素**填充到屏幕上——文本、颜色、图片、边框、阴影。

**触发重绘（Repaint）的操作：**
- 修改 `color` / `background-color` / `visibility`
- 修改 `box-shadow` / `outline`

---

## 四、重排 vs 重绘 vs 合成

```css
/* ❌ 触发重排 + 重绘 */
.box { width: 100px; height: 200px; position: absolute; left: 50px; }

/* ✅ 只触发合成（GPU 加速，性能最好） */
.box { transform: translateX(50px); opacity: 0.5; }
```

| 操作 | 成本 | 触发条件 |
|------|------|---------|
| **重排（Reflow）** | **最高** | 修改几何属性（宽高、位置）|
| **重绘（Repaint）** | 中 | 修改外观属性（颜色、背景）|
| **合成（Composite）** | **最低** | `transform` / `opacity` |

**优化策略：**
```javascript
// ❌ 每次读写都触发重排
element.style.width = '100px'
const height = element.offsetHeight
element.style.height = '200px'

// ✅ 批量读取和写入
const height = element.offsetHeight  // 集中读取
element.style.width = '100px'
element.style.height = '200px'       // 集中写入
```

## 五、关键渲染路径优化

```html
<!DOCTYPE html>
<html>
<head>
  <!-- 1. 关键 CSS 内联 -->
  <style>
    .header { height: 60px; background: #333; }
    .hero { font-size: 24px; }
  </style>

  <!-- 2. 非关键 CSS 延迟加载 -->
  <link rel="preload" href="styles.css" as="style" onload="this.rel='stylesheet'">

  <!-- 3. defer 加载 JS -->
  <script defer src="app.js"></script>

  <!-- 4. 预加载关键资源 -->
  <link rel="preload" href="hero-image.webp" as="image">
</head>
<body>
  ...
</body>
</html>
```

### 优化清单

| 策略 | 说明 | 优先级 |
|------|------|--------|
| **关键 CSS 内联** | 首屏样式直接写在 `<style>` 中 | P0 |
| **defer JS** | JS 不阻塞 DOM 解析 | P0 |
| **图片懒加载** | `loading="lazy"` | P1 |
| **预加载关键资源** | `rel="preload"` | P1 |
| **使用 transform/opacity** | 避免重排 | P1 |
| **减少 DOM 深度** | 简化选择器 | P2 |

## 六、浏览器渲染性能检测

```javascript
// Performance API 测量渲染时间
window.addEventListener('load', () => {
  // 首次内容绘制（FCP）
  new PerformanceObserver((list) => {
    const entries = list.getEntries()
    entries.forEach(entry => {
      console.log(`${entry.name}: ${entry.startTime}ms`)
    })
  }).observe({ type: 'paint', buffered: true })
})
```

**Chrome DevTools 检测：**
- **Performance** 面板 → 录制 → 查看 Main 主线程
- **Layers** 面板 → 查看合成层
- **Rendering** → Paint flashing（高亮重绘区域）

## 总结

```javascript
// 关键渲染路径 6 步：
// 1. HTML 解析 → DOM 树
// 2. CSS 解析 → CSSOM 树
// 3. JS 解析（可能阻塞）
// 4. DOM + CSSOM → 渲染树
// 5. 布局（计算几何位置）
// 6. 绘制（填充像素）

// 优化核心：
// - 减少重排 => 使用 transform/opacity
// - 减少阻塞 => defer JS + 关键 CSS 内联
// - 减少体积 => Tree Shaking + 图片压缩
```
