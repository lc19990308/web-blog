## 前言

竞态条件（Race Condition）是前端异步编程中最容易被忽视的 Bug 源。它的特点是：**时好时坏、难以复现、排查困难**。

> "搜索框输入 'ab'，先发请求 `/api/search?q=a`，后发 `/api/search?q=ab`——但 'a' 的响应比 'ab' 晚到，最终展示的是 'a' 的结果。"

这不是代码"跑错了"，而是"乱序"导致的。本文将系统讲解竞态条件的成因与解决方案。

---

## 一、竞态条件的典型场景

### 1.1 搜索自动补全

```ts
// ❌ 经典竞态 Bug
async function handleSearch(query: string) {
  const results = await fetch(`/api/search?q=${query}`)
  setResults(results) // 如果后发的请求先回来，结果会覆盖先发的正确结果
}
```

### 1.2 页面切换

```tsx
useEffect(() => {
  fetch(`/api/user/${id}`).then(data => {
    setUser(data) // 当用户快速切换 id: 1 → 2 → 3 时，最终显示的可能不是 id=3 的数据
  })
}, [id])
```

### 1.3 自动保存

```ts
// 用户连续修改文档，1s 触发一次保存
// 如果保存 1 的请求比保存 2 晚到，文档内容会被回滚！
```

## 二、解决方案

### 2.1 方案 A：取消过期请求（AbortController）

```ts
class SearchService {
  private abortController: AbortController | null = null

  async search(query: string) {
    // 取消上一次请求
    this.abortController?.abort()
    this.abortController = new AbortController()

    try {
      const results = await fetch(`/api/search?q=${query}`, {
        signal: this.abortController.signal
      })
      return results.json()
    } catch (err) {
      if (err instanceof DOMException && err.name === 'AbortError') {
        console.log('请求已被取消')
        return null
      }
      throw err
    }
  }
}
```

在 React 中使用：

```tsx
useEffect(() => {
  const abortController = new AbortController()

  fetch(`/api/user/${id}`, { signal: abortController.signal })
    .then(res => res.json())
    .then(setUser)
    .catch(err => {
      if (err.name !== 'AbortError') throw err
    })

  return () => abortController.abort() // 清理时取消
}, [id])
```

### 2.2 方案 B：使用请求 ID（忽略旧响应）

```tsx
// 方案 B：忽略旧响应
useEffect(() => {
  let cancelled = false

  fetch(`/api/user/${id}`)
    .then(res => res.json())
    .then(data => {
      if (!cancelled) {
        setUser(data) // 只有最新的请求才更新状态
      }
    })

  return () => { cancelled = true }
}, [id])
```

### 2.3 方案 C：使用 SWR / TanStack Query

```tsx
// TanStack Query 内置防竞态机制
import { useQuery } from '@tanstack/react-query'

function UserProfile({ id }: { id: string }) {
  const { data } = useQuery({
    queryKey: ['user', id],       // key 变化 → 新请求
    queryFn: () => fetch(`/api/user/${id}`).then(r => r.json()),
    staleTime: 1000 * 60
  })

  return <div>{data?.name}</div>
}
```

`queryKey` 变化时，TanStack Query 会自动取消旧的请求（使用 AbortController）。

### 2.4 方案 D：防抖 + 取消

```ts
import { useMemo } from 'react'

function useDebouncedSearch(delay = 300) {
  const abortRef = useRef<AbortController>()

  const search = useMemo(() => {
    let timer: ReturnType<typeof setTimeout>

    return (query: string) => {
      return new Promise((resolve) => {
        clearTimeout(timer)
        timer = setTimeout(async () => {
          abortRef.current?.abort()
          abortRef.current = new AbortController()

          const res = await fetch(`/api/search?q=${query}`, {
            signal: abortRef.current.signal
          })
          resolve(await res.json())
        }, delay)
      })
    }
  }, [delay])

  return search
}
```

**组合拳：** 防抖减少请求频率 + AbortController 取消过期请求。

## 三、Promise 级别的竞态

### 3.1 Promise.race 的风险

```ts
// 限制请求超时
const result = await Promise.race([
  fetch('/api/slow'),
  new Promise((_, reject) =>
    setTimeout(() => reject(new Error('timeout')), 5000)
  )
])
```

**注意：** `Promise.race` 不会取消慢的那个请求——它仍然在后台运行，完成后可能会触发 `.then()`。

## 四、诊断竞态问题

**如何判断是否是竞态 Bug？**

1. **Bug 间歇性出现** —— 有时能复现，有时不能
2. **与网络速度相关** —— 慢网络更容易触发
3. **页面内容"闪烁"或"回滚"** —— 数据从正确变成了旧值
4. **控制台无报错** —— 逻辑没有出错，只是结果不对

**排查工具：**
- Chrome DevTools Network 面板：查看请求顺序
- 模拟"慢 3G"网络复现竞态
- 在 `setState` 前加断点，观察数据来源

## 五、总结

| 方案 | 原理 | 适用场景 |
|------|------|---------|
| AbortController | 取消过期请求 | 搜索、页面切换、自动保存 |
| 取消标记（cancelled） | 忽略旧响应 | 简单场景，兼容性好 |
| TanStack Query/SWR | 自动管理 | 数据获取密集的应用 |
| 防抖 + 取消 | 减少请求 + 取消过期 | 输入搜索 |

**最佳实践：** 新项目优先使用 TanStack Query 或 SWR，它们内置了完善的竞态处理机制。手动处理时，**AbortController + 清理函数**是最可靠的方案。
