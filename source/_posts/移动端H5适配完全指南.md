## 前言

移动端 H5 开发的痛点：屏幕尺寸千变万化、刘海屏/挖孔屏/底部黑条、1px 在不同设备上粗细不一……

本文系统梳理一套经过项目验证的移动端适配方案。

---

## 一、Viewport 设置

```html
<meta name="viewport" content="width=device-width, initial-scale=1.0, maximum-scale=1.0, user-scalable=no" />
```

| 属性 | 说明 | 推荐值 |
|------|------|--------|
| `width` | 视口宽度 | `device-width` |
| `initial-scale` | 初始缩放比例 | `1.0` |
| `maximum-scale` | 最大缩放比例 | `1.0` |
| `user-scalable` | 是否允许用户缩放 | `no` |

## 二、适配方案

### 2.1 rem 方案（经典方案）

以 750px 设计稿为基准：

```javascript
// 动态设置 html font-size
(function flexible() {
  const docEl = document.documentElement
  const maxWidth = 750

  function setRemUnit() {
    const width = Math.min(docEl.clientWidth, maxWidth)
    // 1rem = width / 10
    docEl.style.fontSize = (width / 10) + 'px'
  }

  setRemUnit()
  window.addEventListener('resize', setRemUnit)
})()

// 当屏幕宽度 375px 时，1rem = 37.5px
// 设计稿 100px → 100/75 = 1.333rem
```

```scss
// 使用 scss 函数自动转换
@function px2rem($px) {
  @return ($px / 75) * 1rem;
}

.box {
  width: px2rem(300);   // 300/75 = 4rem
  height: px2rem(200);  // 200/75 = 2.667rem
}
```

### 2.2 vw/vh 方案（现代方案，推荐）

```scss
// 使用 postcss 插件自动转换 px → vw
// postcss-px-to-viewport 配置
{
  viewportWidth: 375,       // 设计稿宽度
  unitPrecision: 5,         // 精度
  viewportUnit: 'vw',       // 转换单位
  minPixelValue: 1,         // 最小转换值
  mediaQuery: false,
}

// 写代码时直接写 px，构建时自动转为 vw
.box {
  width: 300px;  // → 300 / 375 * 100 = 80vw
  height: 200px; // → 200 / 375 * 100 = 53.333vw

  font-size: 14px;  // 小于 minPixelValue 不会被转换
  border: 1px solid; // 边框保持 1px
}
```

### 2.3 rem vs vw 对比

| 方案 | 优点 | 缺点 |
|------|------|------|
| **rem** | 兼容性好（Android 4.0+） | 需要 JS 动态计算，rem 不是精确比例 |
| **vw** | CSS 原生、精确、无需 JS | 低版本兼容性（iOS 8 / Android 4.4+） |

**建议：** 新项目直接使用 vw 方案，辅以 `px` 处理 1px 边框和 font-size。

## 三、1px 问题

在 Retina 屏上，CSS 的 `1px` 实际显示为 2~3 个物理像素，看起来偏粗。

### 3.1 解决方案

```scss
// 方案一：使用 transform: scale(0.5)
.border-1px {
  position: relative;

  &::after {
    content: '';
    position: absolute;
    left: 0;
    bottom: 0;
    width: 100%;
    height: 1px;
    background: #ddd;

    @media (-webkit-min-device-pixel-ratio: 2) {
      transform: scaleY(0.5);
    }

    @media (-webkit-min-device-pixel-ratio: 3) {
      transform: scaleY(0.333);
    }
  }
}

// 方案二：使用 0.5px（仅 iOS 8+ 支持）
.border-half {
  border-width: 0.5px;
}
```

## 四、安全区域（刘海屏/底部黑条）

iPhone X 及以后的机型有刘海和底部虚拟 Home 条：

```css
/* 安全区域适配 */
.page {
  /* 顶部避开刘海 */
  padding-top: constant(safe-area-inset-top);   /* iOS 11.0 */
  padding-top: env(safe-area-inset-top);         /* iOS 11.2+ */

  /* 底部避开虚拟 Home 条 */
  padding-bottom: constant(safe-area-inset-bottom);
  padding-bottom: env(safe-area-inset-bottom);
}

/* 固定底部按钮 */
.fixed-bottom {
  position: fixed;
  bottom: 0;
  bottom: calc(env(safe-area-inset-bottom));
  left: 0;
  right: 0;
  height: 50px;
}
```

## 五、触摸事件优化

```css
/* 移除点击高亮 */
* {
  -webkit-tap-highlight-color: transparent;
}

/* 禁止长按选择文字 */
.no-select {
  -webkit-user-select: none;
  user-select: none;
}

/* 平滑滚动 */
body {
  -webkit-overflow-scrolling: touch;
  scroll-behavior: smooth;
}
```

```javascript
  // 处理点击
})
```

## 八、常见问题

```markdown
Q：rem 计算不准确？
A：检查 html 的 font-size 是否被覆盖，优先使用 vw 方案。

Q：iOS 100vh 包含底部工具条？
A：使用 window.innerHeight 或用 -webkit-fill-available：
   min-height: 100vh;
   min-height: -webkit-fill-available;

Q：不同浏览器字体不一样？
A：使用系统字体栈：
   font-family: -apple-system, BlinkMacSystemFont, 'Segoe UI', 'PingFang SC', sans-serif;
```
