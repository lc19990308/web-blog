用 OpenDesign 补上设计这一环：十个项目产出与 MCP 接入

2026-11-184 分钟阅读更新于 2026-11-18

前端出身缺设计产出这一环，用 OpenDesign 把需求直接落成可交互页面。记录十个项目的产出、交互设计上的迭代方法，以及 stdio MCP 的接入方式

前端做久了，卡点往往不在实现，而在实现之前。

需求文档写“支持搜索”“点开看详情”，字面都对，落到页面上才知道搜索框该占多少位置、详情分几层、返回要不要保留条件。这些话用文字讨论没有结论，画出图来一眼就清楚。

我原来缺的就是这一环。设计稿要么等排期，要么自己拿工具拼，节奏跟不上。用 OpenDesign 之后，需求可以直接变成能点开、能返回的页面，讨论、评审、开发交接都围绕同一份东西进行。

从九月到十一月，本机留下了十个项目。这篇整理其中拿得出的产出，以及我是怎么用它把活干完的，最后写 MCP 怎么接。

项目情况按 2026 年 11 月 18 日本机现存文件与对话记录整理，MCP 部分对照 0.27.1 的源码与文档。

这十项里，六项是可交互的页面，其余是文档与排版。它们解决的是同一件事：把口头或文字里的需求，变成可以指着讨论的对象。

其中一个值得单说的是复刻项目。1440px 截图比对下来差异 0.164%，听起来接近满分，但它的前提是固定视口与固定状态，报告里也没做路由爬取和交互探测。这张数字能证明那一屏还原得准，不能外推到整站。

海斗宝典：一次完整的产品设计

这个项目从零到可交互原型，跨了需求、内容、视觉和交互四层，最能说明这套流程怎么跑。

从调研到设计输入

起点是一个英雄与强化速查工具。我没有直接进入画图，先让它调研参考站点，输出需求说明、MVP、PRD、设计风格与设计体系。

首版定七类页面：英雄列表、英雄详情、海克斯列表、海克斯详情、收藏、最近查看、数据说明。

文档写完后又追了一轮：现在能否出稿，缺什么。这一问把“文档齐了”和“能出稿”区分开。真正要补的是内容——哪个英雄配哪个强化、出装引用哪张图、无数据时显示什么。

补齐之后，设计输入的规模如下：

内容 数量
英雄 8
海克斯内容 12
装备内容 27
英雄与强化关联 24 条
示例出装 8 套
页面与异常状态 26 个
Lucide 图标 14 个

26 个状态场景写进了设计资料，实际接入页面的是其中一部分。

素材作为独立环节

图片单独处理。最终落到本地 334 张：英雄头像 8、海克斯图标 180、装备 114、英雄技能 24、召唤师技能 8，与素材目录一致。

这里容易混的是图标和内容的差别：180 张海克斯图标对应的是图鉴素材，进入首版内容的只有 12 个海克斯。图标供页面取用，内容是核对过的文案，两类工作分开管理。

采集范围做了限制：只读首页、八个英雄详情、海克斯列表与三个公开详情页，不递归全站，不推测地址。常规符文在限定页面内没有明确引用，就没有建空目录，也没有拿海克斯图标替代。

授权单独留了记录。页面可访问、robots 允许抓取，与允许再分发是两件事。素材按个人练习使用，公开发布前需要另行确认。

从图鉴到数据首页

第一版按图鉴做。看过参考站点后，首页的信息量明显不足：英雄排行、海克斯排行、装备排行、分阶段的海克斯胜率都没有。

于是补了 v1.0 需求说明与 PRD，再把数据首页、三类排行、装备详情与条件胜率接入原型。

接入之后暴露出交互问题。排行页被我做成搜索框、下拉筛选、排序按钮平铺，外面套手机壳，实际体验仍接近后台表单。原话是“表单查询搜索更像网页端功能，而不是 app，交互体验很差”。

修改分三处：搜索独立成页；筛选收进底部面板，确认后才应用，关闭不提交；导航让各栏目保留浏览位置，详情按层级进出。

这一轮之后提需求的方式变了。与其说“做得好看点”，不如说“首层只做快速录入，复杂内容进二级页”，后者可以逐条验证。

对局助手的形态收敛

后续需求更贴近实际使用：对局中要知道这局怎么玩，需要快速录入当前英雄与已选强化，并查看出装，入口还要求语音、对话与拍照。

形态调整过三次。先是首页大卡片，再是底部卡片加“开始本局”，最后是全屏工作台。每次问题相同：多一步操作。

收敛后的结构：

  • 底栏中间固定“对局助手”，收藏移入设置
  • 未选英雄时，首层是搜索与少量匹配结果，点选即录入
  • 已选英雄时，显示英雄、已选强化摘要与一条玩法提示
  • 三个快捷入口：录海克斯、查出装、问助手
  • 完整攻略、候选比较与连续对话进入二级页，返回可回到面板
  • 关闭面板回到原页面，对局记录保留

写这篇时在隔离浏览器中走了一遍“对局助手 → 亚索 → 查出装”，面板与出装页均正常打开，控制台无报错。

去掉模板感

功能增多之后，页面开始有模板痕迹：青色描边偏多，金色装饰承担强调，内容普遍套卡片。我提出“把设计稿 AI 的味道去掉”。

调整方向是减描边、减金色、拆套框，收紧标题与数据字号，信息改用连续列表加分隔线组织。文案换成“玩法要点”“对局问答”“确认录入”这类直接表达。

改后的样式已落到文件，验收留待后续。

怎么用它干活

用下来比较稳定的三条。

一次推进一层

需求不清先写文档，资料缺先补素材，出了原型再查流程，交互确认后收视觉。混在一起提，理解容易偏。

系泊项目有过一次偏差：我只想补数据看板，它按重新出一套原型来做。原话是“没让你重新出原形，让你补充原型的数据面板而已”。把范围写死——“只改看板区域，其他模块不动”，再列出通过率、缺陷、审核状态、活动信息的排列要求，一次就对。

要求写成可验证的句子

“做得干净一点”没有验收标准。“筛选面板关闭时不提交条件，返回列表保留位置”，每一条都能试。前者反复几轮还在猜，后者一轮收敛。

交付要自己走一遍

检查路径固定为：从哪进入、点击什么、看到什么、返回状态是否还在，再补窄屏、弹层、错误态与长文案。

巴厘岛项目是反例。后期确实调整了地形、道路、材质与标注，但最后一轮截图停在加载页。交付记录写的是代码层面定位到问题并完成修改，缺少能证明异常多边形消失的画面。这类情况只能记为改动已提交、画面待复核——语法检查通过，不等于渲染正确。

MCP：让开发工具直接读项目

桌面端适合看着改。MCP 的作用是让 DSH、Claude Code 这类客户端直接调工具读写项目，把设计产物带进开发对话。

链路如下：

三个入口不要混：

入口 用途
桌面界面 建项目、预览、提反馈
CLI 终端与脚本使用，mcp 子命令启动 MCP 服务
MCP 供外部 AI 客户端按工具调用

此外，OpenDesign 自身可以挂载其他 MCP 服务，也能将 DSH 作为 agent 运行，方向相反，配置不通用。

第一步：复制本机配置

在 Settings → MCP server 复制对应客户端的配置，命令、参数与环境变量完整保留，尤其是数据目录与 daemon 发现、启动相关字段。

到 0.27.1 为止，这套 MCP 使用 stdio。参数中出现的 http://127.0.0.1:... 是 daemon 地址，不是 MCP 地址，不要按 HTTP MCP 填写，也不要自行拼接 /mcp。

本机有一处需要注意：

这是 macOS 自带的字节转储工具。command 直接写 od，启动的是它而非 OpenDesign，通常也不报错。桌面生成的配置使用绝对路径与运行参数，以该配置为准。

第二步：填入 DSH

在 DSH 的 MCP 管理页添加服务，传输方式选 stdio，executable、args、env 分开填写，不要把整段 JSON 放进命令框。

本机 DSH 中已存在名为 open-design 的记录，状态为关闭，注册工具数为 0。文中工具名取自 0.27.1 源码的 TOOL_DEFS，本机尚未连通验证。

第三步：先只读，再写入

常用工具：

用途 工具
查看项目与当前打开文件 list_projects、get_active_context
查看项目信息与文件清单 get_project、list_files
读取文件、搜索内容 get_file、search_files
一次获取入口及引用资源 get_artifact
建项目、建产物、写文件 create_project、create_artifact、write_file
启动任务、查看进度、取消 start_run、get_run、cancel_run

接入后先跑只读指令：

判断依据是能看到具体工具调用并返回文件内容。只有模型自述“已读取”，不足以说明连通。

get_artifact 比逐个 get_file 省事，入口引用的同项目文件会一并返回，CDN 与超限资源跳过。项目 ID 建议写明——get_active_context 存在有效期，在 OpenDesign 中停手数分钟后可能失效，交接时容易读错对象。

只读跑顺后再提修改，并限定范围：只改助手首层、保留底栏，或另建副本迁移结构。这套工具包含写入与删除操作，明确对象与边界会更稳妥。

0.27.1 支持不开启 GUI 运行，窗口不必常驻。前提是 daemon 可达；能否自动拉起，取决于配置中是否包含相应的发现与启动字段。

这一环补上之后

十个项目沉淀下来的是一组可直接续改的文件：需求、原型、素材索引、示例数据、脚本、审计记录与正式文稿。它们让需求讨论有具体对象，也让开发交接少一次背景重述。

更实际的变化在能力上。过去需求到我这里，先卡在“怎么画”；现在可以当天出一版能点的页面，把讨论拉回具体问题。三方评审、方案对比、开发估点这类场合，我都能带着产物参与，而不是等设计排期。

这个转变主要来自实操。海斗宝典那几轮调整，价值不在最终稿，而在于摸清了什么样的描述能被实现、什么样的要求只能靠点出来判断。

后续要推进的几项也明确：海斗宝典的语音与识别接入真实服务，统计替换为有来源的数据；巴厘岛重新截图完成渲染验收；博客主题完成源码迁移。MCP 这条线先把本机关闭的记录打开，跑通一次只读，再用于改文件。
