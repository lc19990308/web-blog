把技术提纲做成可翻页 HTML：AI_Animation 实战

2026-08-074 分钟阅读更新于 2026-08-16

用 AI_Animation 的 ppt-animation Skill 把技术提纲做成单文件 HTML 演示：安装、提示词、验证方式，以及它适合和不适合解决的问题。

我原本以为，给一次技术分享准备材料，最自然的起点是新建一个 PPT。后来发现真正花时间的不是写提纲，而是把每一页的层级、图示和翻页节奏整理到能录屏的程度。

AI_Animation 处理的是这一步。它不是一个要在业务项目里 import 的动画库，而是一组给 AI 编程代理用的 Skill。把主题、受众和演示节奏说清楚后，Agent 生成一个可独立打开的 HTML 文件。页面内的图形、样式和交互都在这个文件里，适合技术讲解、课程录屏和内部分享。

这篇文章用仓库里的 ppt-animation 作为例子。下面的演示就是按这个方式做出的成品，可以用键盘方向键、鼠标滚轮、点击左右区域翻页。

它实际提供了什么

项目目前提供六个 Skill。它们的共同点是：输出是可以交付、可以直接在浏览器里打开的页面，不要求你先搭一套前端工程。

Skill 适合解决的任务
ppt-animation 分页演示、课程录屏、技术讲解
flowchart 流程、概念、时序和原理说明
network-protocol-viz TCP/IP、路由、报文等网络协议可视化
dynamic-archify 架构图、数据流、状态机，以及导出图片或视频
scholar-notes 带图示的学习笔记与技术摘要
card-theater 侧边解说配合卡片轮播的分步叙事

不要把这六个名字当成一组必须全部安装和调用的功能。先看内容的表达形式：需要一页一页讲，就选 ppt-animation；需要读者自己观察数据怎样流动，就选 flowchart 或 dynamic-archify。选错容器，后面再堆 CSS 也很难自然。

这里真正有用的信息有四类：

  1. 演示用途决定字号和信息密度。录屏需要大字和少量短句，文档阅读可以放更多细节。
  2. 页数与页面清单限制内容膨胀。六页不是硬规则，但每页只解决一个问题。
  3. 视觉约束比“科技感”更可执行。直接写颜色、禁用项和是否使用真实素材。
  4. 交互与交付形式决定生成结果能否直接使用。这里要求了键盘、滚轮、点击和单文件交付。

ppt-animation 的特点不是自动替你写对内容，而是把“翻到下一页后，标题先出现，图示和文字随后出现”这件重复的前端工作变成固定能力。内容仍然需要你自己判断：架构关系是否正确，术语是否准确，读者能否在一页内理解。

生成后，不要只看截图

HTML 能打开不等于它已经能用于演示。我会按下面四项过一遍：

  • 断网打开：确认字体、脚本、图片没有把关键内容留在外部 CDN。
  • 逐页翻看：每一页都应先出现标题，再出现支撑它的文字或图形；不要让所有元素同时弹出。
  • 检查三种输入：方向键、滚轮和点击是否都能翻页，最后一页和第一页是否正确处理边界。
  • 按目标屏幕录一遍：在笔记本和投屏分辨率下各看一次，确认正文没有被裁切，页码和进度条不会挡住内容。

如果页面服务于博客或文档，可以像本文一样嵌入 iframe，同时保留“在新窗口打开”的链接。这样文章的阅读节奏不会被演示本身打断，读者又能在需要时获得完整画布。

它的边界在哪里

这类 Skill 很适合把一次性的讲解材料、原理图或架构图迅速变成更易读的页面。它不替代需要长期维护的产品前端：复杂状态、权限、真实数据、无障碍要求和跨页面导航，仍然应该进入正常的工程化项目。

另一个边界是事实。Agent 可以画一张很顺眼的协议流程图，却不能替你证明时序正确；它也能排出一页漂亮的架构图，却不会自动知道服务之间真正的依赖。把生成结果当成第一版，再按资料或代码核对，才是可靠的使用方式。
