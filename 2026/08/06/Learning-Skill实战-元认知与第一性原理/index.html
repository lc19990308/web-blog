Learning Skill实战：把元认知和第一性原理变成可执行能力

发表于 2026-08-06 分类于 AI 阅读次数：
从 0 到 1 打造一个学习导航器 AI Skill：需求设计、两轮审查迭代（6/10 到 MVP）、方法选择矩阵、掌握证据体系、错因分类，以及前端转产品和 Playwright 两个实战案例

前言

你有没有这样的经历：想学一个新领域，打开收藏夹里几十个教程链接，收藏=学会；或者让 AI 帮你制定学习计划，得到的是一份”从入门到精通”的百天大纲，然后第一天就放弃了。

问题不在”没有计划”，而在计划不是为你的目标、基础、时间和风险定制的，也没有任何验证机制告诉你学没学会。

这篇文章记录我从 0 到 1 打造一个 learning-navigator（学习导航器）AI Skill 的全过程：它如何把”元认知”和”第一性原理”从口号变成可执行的机制，中间经历的两轮严格审查（第一次被打 6/10），以及两个真实领域的实战结果。

核心定位：它不是替用户堆学习方法，而是先诊断目标和约束，再选择方法，并用真实产出来校准路径。

一、需求：我想要什么样的 Learning Skill

最初的需求是这样的：

我想制造一个 Learning Skill，能快速让我学习一门陌生的技能和陌生的领域。它具备提取元认知、抓核心的能力，掌握很多优秀的学习法，会根据情况分析来决定规划学习方法，具备第一性原理。

拆解一下，四个关键词：

  1. 元认知：能意识到”我卡在哪、为什么卡、该怎么改”
  2. 抓核心：不淹没在细节里，直取领域的核心机制
  3. 方法库：掌握多种学习法，按情况选择
  4. 第一性原理：从基本原理推导，而不是堆砌表面知识

听起来很美好，但”元认知”和”第一性原理”恰恰是最容易被做虚的两个词——因为它们需要机制，而不是形容词。

二、第一版计划：学习闭环的骨架

第一版设计了一个学习闭环：

核心设计思想：

  1. 先定义”最终能完成什么”，而非”要看多少课”
  2. 区分知识类型：概念理解、工具操作、问题求解、项目交付、表达沟通、动作技能
  3. 第一性原理落地：强制输出领域最小模型——核心对象、关键关系、因果机制、边界条件、常见误解
  4. 按条件选方法：
    • 概念与长期记忆 → 主动回忆、间隔复习、交错练习
    • 新手复杂技能 → 示例拆解、模仿后变式练习
    • 工程与工具 → 最小可运行任务、错误日志、真实交付物
    • 推理类领域 → 费曼解释、反例、从约束推导
    • 高表现技能 → 刻意练习、即时反馈、针对薄弱点重复
  5. 每个学习周期生成中文任务卡：时间预算、输入材料、练习动作、交付物、过线标准、失败降级、复习节点
  6. 学习完成以作品、解题、演示、录音或真实操作为证据，而不是”看完了”
  7. 验证而非自我宣称：完成后用三类陌生任务前测

看起来挺完整？我当时也觉得可以了。但让 AI 审查后，被打了个 6/10。

三、第一次审查：6/10，七个漏洞

审查结论很直接：方向对，但缺少能让它稳定决策、避免误导、验证真实效果的关键机制。七个漏洞按严重程度分级：

P1（必须修复）

1. 方法选择不可执行
计划说”按情况选方法”，但没定义输入字段和决策规则。没有目标类型、时限、起点、反馈可得性、风险等级、可投入时间的权重，最后很可能退化成每次都罗列”主动回忆、费曼学习法”的通用建议。

2. “陌生领域”边界过宽
编程、外语、摄影、医学、投资、网络安全的学习风险和验证方式完全不同。需要风险分层：高风险领域只做基础概念、权威来源导读和模拟练习，不提供可直接执行的专业决策或操作指令。

3. 把”产出”误当成”掌握”
做出一个作品，可能是模仿、AI 辅助或只适用于原题。需要至少三层证据：独立完成、换情境迁移、延迟复现；每层都要定义速度、正确率、质量标准或评价量表。

4. “第一性原理”有滥用风险
语言、工具配置、行业规范、安全流程中，大量内容本质上是约定、经验或标准，不能从基本原理推出。应把内容区分为：可推导机制、必须记住的事实、应遵循的规范、待验证的经验——而不是强行从第一性原理重建一切。

P2（重要但可后置）

5. 缺少学习输入的质量控制：规划了”怎么学”，没规定”学什么材料”。需要来源分级、版本/发布日期、原始资料与二手解释的区分。

6. 缺少持续状态模型：需要一个唯一的当前学习状态（已掌握、易错点、待复习、卡点假设、下次行动），否则每轮对话都从头规划。

7. 验证方案不足：三个陌生任务只能证明它会”生成看似合理的计划”，不能证明学习有效。应预设对照指标。

审查给的实现目标很精确：

根据目标、基础、约束和风险，为一个学习周期生成可验证的学习行动，并根据证据更新下一周期。

四、优化：从”方法清单”到”决策与校准系统”

基于审查意见，定位彻底改了——不再是”学习方法清单”，而是：

learning-navigator 是一个学习决策与校准系统，负责把陌生领域转成可验证的学习周期。

第一版范围（明确收缩）

只解决一个问题：**在有限时间内，让用户从陌生状态走到”能独立完成一个定义清楚的任务”**。不承诺培养长期专家，不在医疗、法律、金融交易、安全攻防等高风险领域给出可执行专业决策。

启动诊断：最多五项

  1. 最终要独立完成的任务，以及谁/什么标准验收
  2. 截止时间和实际可投入时间
  3. 当前基础——用一个小任务或口头解释证明，而非自评”会/不会”
  4. 可用环境、材料、工具和是否能获得反馈
  5. 风险边界

信息不足时，不输出长计划，先安排一次 30 分钟基线任务，再只生成一个暂定的 3 天冲刺。

掌握证据：四层递进

不以”看完、做过、感觉懂了”判定进步：

  1. 有材料或示例时完成（支架下）
  2. 移除提示后独立完成（独立）
  3. 换一个情境完成迁移任务（迁移）
  4. 延迟复现，检查保留情况（保持）

五、第二次审查：三个 P1 缺口

优化版被评价为”已经从’学习方法清单’进化成了可运行的系统”，但仍有三个必须先修的问题：

P1-1：元认知仍未真正落地。 计划提到诊断、复盘和调整，但没有要求学习者预测表现、记录实际表现、识别错因、比较策略是否有效——所以它仍是”教学计划生成器”，不是元认知教练。修复：加入固定闭环 学习前预测 → 执行 → 独立测试 → 实际结果 → 错因分类 → 保留/替换策略，每轮至少记录预期得分、实际得分、置信度、主要错因和下一轮策略变化。

P1-2：掌握证据没有可执行的评分定义。 “独立完成、迁移、延迟复现”是对的，但不同领域如何判定通过没有定义。修复：练习开始前明确评价者是谁、评分量表是什么、通过线是多少、允许哪些辅助。

P1-3：高风险边界太粗。 需要三档：可直接学习的基础知识 / 只能在模拟监督下练习的内容 / 必须转交权威教材或专业人士的内容，每档规定允许的输出。

还有一批 P2 增强：基线诊断改为 5/15/30 三档；方法矩阵增加”反馈可得性、材料可靠性”两个变量；复习间隔不写死 72 小时；来源冲突处理；状态账本先会话内维护。

六、最终实现：learning-navigator 的五个模块

经过两轮迭代，最终实现的 Skill 结构：

模块 1：建立学习契约

从用户已有信息提取五项（只补问缺失且会改变当前决定的信息，最多五项）：

  1. 可观察目标：最终要独立完成什么任务？谁或什么标准验收？
  2. 约束：截止日期、单次和总可投入时间、可用工具
  3. 起点：用一次解释、小题或最小操作证明当前能力——不接受”会/不会”自评
  4. 材料与反馈：有哪些材料？是否有自动测试、同伴、老师或专家反馈？
  5. 风险：是否涉及健康、法律、资金、真实生产系统、危险设备或他人安全？

基线档位：截止很近或目标很小用 5 分钟；常规起步 15 分钟；需要区分多个薄弱点 30 分钟。总时间不超过 30 分钟时，基线最多占 5 分钟，剩余时间必须用于一个可观察的主动练习。

风险门（最终版三档）：

等级 处理方式
低风险 可设计真实练习和独立任务
受控风险 只在沙箱、模拟环境、监督或可回滚条件下练习；先写停止条件
高风险 只提供基础概念、权威材料定位、案例讨论和模拟评估；要求合格监督或专业人士确认

法律、医疗、投资决策、生产变更默认至少为受控风险。

模块 2：建立领域最小模型

每类内容明确标记证据等级：

  • 机制：对象、关系、因果或工作原理——可用第一性推理检验
  • 事实：必须记住但不能从原理推出的术语、数据、接口或规则
  • 规范：行业约定、工具惯例、法律/安全要求——不要假装能从原理推导
  • 边界：反例、失败模式、前置条件与禁止事项

每条结论标记为 来源证据 / 合理推断 / 待验证。

模块 3：方法选择矩阵

一次冲刺选 1 个主方法 + 至多 1 个辅助方法，并写明选择依据：

主要障碍或目标 主方法 可选辅助 直接证据 不要这样用
不理解概念 对比示例与受限解释 主动回忆 不看资料解释因果并判断反例 只画思维导图或重复阅读
知道步骤但不会做 完整示例→半完成→独立变式 最小项目 无提示完成相邻变式 直接投入大项目
要记住事实/术语 主动检索 间隔复现 延迟后正确取回并说明差异 把高亮、重读当检索练习
易混淆相近情形 对比练习与交错练习 错误卡 新案例中说明选择理由 陌生时随机混合大量主题
需要诊断/推理 约束推导与反例 口头讲解 解释取舍并处理反例 把第一性原理当作忽略规范
操作技能 小而有反馈的刻意练习 录制/回看 错误率、时间或质量达阈值 无反馈高风险下盲目重复
时间少必须交付 最小可交付任务 针对性检索 交付物达到最低验收线 假装已建立长期理解

模块 4：生成短学习冲刺

默认 1-3 天或 3-5 个学习区块，而不是一次性安排数周。每个区块包含：

  • 目标任务与时长
  • 输入与边界（材料来源、版本、风险限制）
  • 主动练习（解释、检索、操作、变式任务或模拟——不能只阅读）
  • 反馈（自动检查、量表、同伴/专家反馈，或明确说明缺失）
  • 交付物（答案、演示、运行结果、笔记等可检查证据）
  • 通过线（开始前定义评价者、维度、阈值、允许辅助）
  • 失败降级（过难时改用哪个更小的变式；连续失败停止加新材料）
  • 复现日期（由截止期和本次表现确定，不机械固定）

模块 5：执行元认知闭环

每个区块结束时依次执行——这是整个 Skill 的灵魂：

  1. 预测：学习者先预测完成度、耗时或得分，并给出置信度
  2. 独立尝试：移除不必要提示完成任务
  3. 比较：对照预定义量表记录实际结果
  4. 分类：标注主要错因
  5. 调整：只依据已记录的错因、证据和约束改变下一轮；说明改了什么、为什么改

七、掌握证据体系：你怎么知道学会了

状态等级（禁止越级宣称）

状态 最低证据 不应声称
未尝试 尚无独立动作 已学习
支架下完成 使用示例、提示或协作完成 已独立掌握
独立完成 在原情境中无关键提示完成 可迁移或长期记住
迁移通过 改变素材、参数或情境后仍完成 长期保持
延迟保持 间隔后独立复现且达到通过线 永久掌握

错因分类（M/P/R/F/L/B）

代码 诊断信号 下一步
M 模型缺失 无法解释为什么、混淆因果 用对比示例补最小模型
P 步骤不熟 知道原理但漏步、顺序错 缩小到一个步骤做变式
R 检索不足 看见答案会、独立时想不起 主动检索、对比卡、间隔复现
F 反馈/材料问题 标准冲突、版本不明 核验权威来源
L 负荷问题 超时、连续卡住、投入感低 缩短区块、减少新内容
B 边界/风险问题 操作不安全、超权限 停止真实操作，改模拟

关键规则：只记录最能解释本次失败的一至两个代码，不要把”努力不够”当默认诊断。

八、实战案例 1：前端转产品经理（3 天冲刺）

一位有交付能力的前端开发者想转产品方向，Skill 诊断出的真实缺口不是”不会写 PRD”，而是”为什么做、为谁做、如何判断做对”。

领域最小模型：

  • 机制：用户在场景中完成任务受阻 → 形成可验证的问题假设 → 选择最小方案 → 观察行为和业务结果 → 决定继续、调整或停止
  • 规范：PRD 不是产品经理工作的核心；没有证据就应标为假设，不能用”我觉得用户需要”代替调研
  • 边界：前端能力能帮助判断可行性和快速原型，但不能替代用户理解与商业判断

主方法：用一个真实功能完成最小产品发现项目。辅助：主动复述与反例。不建议先刷课程或背模板——因为已有交付能力，缺的是判断框架。

3 天冲刺：

天数 任务与交付物 通过线
第 1 天 选熟悉的功能（用户列表/表单/搜索），15 分钟写：目标用户、场景、任务、阻碍、证据、假设、暂不做的方案 → 一页问题简报 能把”用户问题”与”想加的功能”分开；每条标为证据或假设
第 2 天 写发现计划：6 个不诱导用户的问题、三类行为证据、一个核心行为指标和一个风险指标 指标衡量用户行为，不只衡量页面是否上线
第 3 天 写一页 MVP 决策卡：问题、证据、待验证假设、最小范围、不做什么、成功指标、三个验收标准；换一个功能 20 分钟拆解 MVP 只服务一个明确行为；存在可观测成功指标

卡点预判：把页面优化写成需求清单（M）；没有证据来源（F）；范围越写越大（P）；连续两次写不下去（L）——每个卡点都有对应的降级动作。

九、实战案例 2：Playwright E2E 测试（3 天 × 90 分钟）

目标：从零写出 3 个稳定的本地 E2E 测试。Skill 给出的不是”去看 Playwright 文档”这种废话，而是精确到分钟的任务卡：

第 1 天（90 分钟）：

  1. 0-5 分钟：定下页面和三条行为
  2. 5-20 分钟：预测”多久能跑通第一个测试”+ 置信度，然后安装
  3. 20-55 分钟：按文档创建第一个测试
  4. 55-75 分钟：只修复第一个阻塞点，记录卡点类型
  5. 75-90 分钟：关掉文档，独立补第二个断言

通过线：至少一个测试可运行；能解释 goto → locator → expect 各做什么。

第 2 天： 不看文档重写测试骨架并预测耗时 → 只查当前需要的 locator → 写出第二个测试 → 连续跑三次修不稳定 → 记录置信度偏差和错因。

第 3 天： 独立起草第三个测试（覆盖不同路径）→ 迁移检验（换掉一个非核心变量确认思路成立）→ 干净终端跑三次 → 不看代码用自己的话解释三个测试。

最终通过线：三个测试对应三条不同用户行为、连续三次 3 passed、第三个测试首次独立起草、能说明 locator 为什么比 CSS 层级选择器稳定。

每天只更新一张状态卡（六项）：

十、核心设计哲学：为什么”克制”是它的灵魂

回头看，这个 Skill 从 6/10 到可用的关键，不是加了更多功能，而是明确画了三条线：

1. 不越界

高风险领域只给概念和模拟，不给可执行专业决策；信息不足时不编长计划，先给基线任务。

2. 不假精确

“产出”不等于”掌握”——通过线必须在开始前定义，证据分五级状态，不能越级宣称；复习间隔由截止期和表现决定，不写死 72 小时。

3. 不自嗨

元认知闭环强制”预测→执行→比较→分类→调整”，让每轮调整都由证据触发，而不是始终输出同一份模板。

一个学习 Skill 最大的失败，不是方法不够多，而是让用户以为”看完计划”就是”学会”。

总结

从”我想要一个会元认知、会第一性原理的 Skill”到真正可用的 learning-navigator，我学到的东西：

  1. 元认知是机制不是形容词：预测-执行-比较-分类-调整的闭环，比任何”教你反思”的提示词都有效
  2. 第一性原理要分层：可推导的机制才用原理推导，事实、规范、经验要区分对待，不能强行重建一切
  3. **审查要请”敌人”**：6/10 的第一次审查救了整个项目——P1 漏洞（方法选择不可执行、产出≠掌握、风险边界）每一个都会让 Skill 沦为花架子
  4. 通过线必须在开始前定义：评价者、量表、阈值、允许辅助，缺一不可
  5. **错因分类代替”努力不够”**：M/P/R/F/L/B 六类诊断，让调整有依据，复盘不空转
  6. 收缩范围是设计：第一版只解决”从陌生到独立完成一个任务”，不做万能课程生成器

最后送你一句话，也是这个 Skill 的第一原则：

学习的终点不是”看完了”，而是能在没有提示的情况下，独立完成一个可验证的任务。
