03 / 生成路径

从一句需求到一个可交付文件

Skill 的工作不是替代事实判断，而是把重复的布局、动效和交互收敛成稳定步骤。

01

写出提纲

02

选定 Skill

按内容形态选择演示、流程或架构。

03

给出约束

主题、页数、用途和操作方式。

04

打开并校验

检查互动、版面和技术事实。

04 / 提示词

把抽象偏好改成可检查的约束

“做得炫酷”无法验收。说清颜色、页数、读者和输入方式，输出才有方向。

PROMPT BRIEF6 SLIDES
  • 用途10 分钟内部技术分享并录屏
  • 主题白底、深色字、绿和珊瑚红点缀
  • 内容需求、架构、开发、测试、发布
  • 交付单文件 HTML，支持键盘、滚轮与点击

05 / 验收

别只看一张好看的截图

✓

断网打开确认关键字体、脚本和图形不依赖外部资源。

✓

逐页翻看标题、正文、图形依次出现，而不是同时跳出。

✓

测试输入方向键、滚轮、点击和边界页都能正常处理。

✓

按目标屏幕录制投屏或窄屏下不裁切正文，不让控件挡住内容。
