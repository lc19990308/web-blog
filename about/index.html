LC

我是一名前端开发者，也持续做技术学习和工程实践的记录。这个博客从 2021 年开始更新，最初用来整理 JavaScript、Vue 和 CSS 的学习笔记；现在更关注一件事：把一个技术选择、一次排障或一条工作流，写成别人可以核对、复用和继续讨论的过程。

这里不是产品公告，也不追逐每日资讯。文章会保留问题的前提、方案的边界和验证方式。遇到资料不完整、工具行为不稳定或结论无法复现时，我会把它们写出来，而不是用结论把过程盖过去。

我关注的方向

前端实现与体验

JavaScript、TypeScript、Vue、React 和 CSS 是长期主线。我关心组件如何组织、状态如何流动、页面怎样在不同设备上保持清楚，以及浏览器能力如何真正改善用户体验。

工程化与交付

构建、测试、容器化、发布和 Git 工作流决定了代码能否稳定到达用户手里。相关文章会尽量给出小的可验证闭环，而不是只罗列工具名称。

浏览器性能与图形计算

性能优化、Web Worker、WebAssembly、WebGL 和 WebGPU 是正在持续补足的方向。这里更重视测量、输入规模和运行边界，不把某一个框架或语言写成万能解法。

AI 辅助开发与知识工作流

我也在研究如何把 AI 用在真实开发和学习中：从源码与文档核验，到可复用 Skill、架构图、流程图和知识库整理。工具本身不是结论，能被检查的产出才是。

我怎样写文章

一篇文章通常从一个具体问题开始：一个 API 到底怎么用，一份配置为什么失效，或者某个方案是否真的值得引入。写作时尽量遵循四个顺序：

  1. 先说明问题发生的条件与目标。
  2. 用官方文档、代码或实际页面确认关键事实。
  3. 给出足够小的示例，并写清它不覆盖什么。
  4. 用构建、测试或浏览器结果验证，留下可以继续追问的入口。

这也是为什么一些旧文章会持续修订。技术文章不是一次性输出，过期的命令、无来源的性能数字和无法运行的代码都应该被替换。

从哪里开始读

  • 想补语言与类型系统，可从语言与类型系统专题进入。
  • 想处理组件、状态和页面实现，可看界面与框架专题。
  • 想解决构建、测试、发布或架构取舍，可看工程与架构专题。
  • 想了解浏览器、网络与性能，可看浏览器与性能专题。
  • 想阅读 AI 编程、知识整理与可视化实验，可看AI 与创作实验专题。

现在在学习什么

目前仍在持续深入 TypeScript 与前端工程化，也在推进浏览器图形计算、WebAssembly、系统设计，以及 AI 辅助研发中的知识沉淀与任务分解。方向会随着实际项目变化，但判断标准不变：能否形成可交付、可验证的结果。
